前端栈评估 · 内部汇报

用 React 重写
ACP New Console (DevOps)

前提:AI 作为主力开发。评判标准只有一条——哪种栈让 AI 产出更快、更稳、更省事。
下文每个数字均为本仓库实测 实测。

结论先行 · TL;DR四个维度,React 都更适合 AI 来写

① 生态

CNCF / AntD 主流,AI 可抄可借鉴;告别私有 beta 库

② 效率

AI 更顺手 · 单插件秒级启动 · 增量构建快一个量级

③ 质量

框架内建 DI 易 mock,AI 顺手补单测

④ 灵活

组件级可插拔:图表 / 表单控件 / 导航项独立插件

一句话:AI 越是主力开发,React 相对 Angular 的优势越被放大。

维度 ① 生态AI 的"可抄素材池"

  • CNCF / 主流控制台(Backstage、Grafana、Argo、Headlamp…)几乎都是 React——AI 复用、借鉴范式时语料充足、改造顺手
  • AntD 5 有 LTS、安全更新、海量组件;本项目新前端体系本身就是 Backstage 式 blueprint/extension,借鉴成本极低
  • 现状深度绑定自研 @alauda/ui 9.x（beta）:社区为零、升级困难、AI 无语料、出问题只能自扛

React 让 AI 站在巨人肩膀上;Angular + 私有库让 AI 从零造轮子。

维度 ② 效率AI 主导下差距最大

2.1 AI 友好 实测

普通函数 + JSX + hooks,无 decorator/NgModule/Zone/DI 仪式 → LLM 首过正确率高。

本会话 AI 一口气搬完 PipelineRun 详情 + Task 树 + ANSI 实时日志 + 单测。

2.2 启动 实测

单插件(左导航级)独立 dev,~1.6s 服务就绪 / ~5.7s 首屏。

Angular 连单插件 dev 也要先构建整个 host 再起 webpack serve。

2.3 构建 实测

rsbuild/rspack(Rust)本身快;MF 只重建改动的 remote。

单插件冷构建 8.2s vs 92.2s。大型 Angular 单体全量可达 40 分钟级。

AI 高频改动 → 反馈环越短越值钱。启动/构建快一个量级 = AI 迭代快一个量级。

维度 ③ 质量AI 的质量闭环

  • 新架构内建依赖注入(useApi(ApiRef))→ 测试里轻松 mock K8sApi / 权限,单测和小 E2E 都好写
  • 对比:Angular 的 TestBed 配置重,AI 写起来啰嗦、易错
  • 本仓已有 vitest 单测(均为 AI 顺手补):编排模型 model.test任务树 buildTaskTree.testANSI 解析 ansi.test

闭环:AI 写实现 → AI 补测试 → DI 易 mock → 回归有保障。

维度 ④ 灵活性组件级可插拔

  • blueprint / extension + 扩展点:单独发一个插件就能挂一个监控图表 / 加一个动态表单控件 / 塞一个导航项,不动主程序
  • 本仓已有真实例子:dynamic-form 表单控件topology 拓扑引擎navParent 导航扩展点
  • "小而独立的插件"正是 AI 最擅长的粒度;Angular 单体很难做到这种细粒度可插拔

加扩展 不改宿主 → 风险小、可并行、适合 AI 批量产出。

诚实面对 · 问题与应对不回避,给方案

问题应对
UI 风格:AUI vs AntD 有差异,难像素级一致AntD 5 design token 可调到接近;更稳的是统一到新规范,而非复刻旧 AUI
迁移要时间MF 增量灰度:新旧插件共存、按域逐切、可回退;地基 + 旗舰 Pipeline 已跑通
React 太灵活 → AI 易生成不一致代码用 blueprint 规范 + lint + 目录约定 给 AI 立护栏(本仓已有范式)

React 的"灵活"对 AI 是优势,但需要架构约定兜底——主动说出来,反而更可信。

一句话总线 · 下一步

前提是 AI 主力开发 → 评判看「AI 顺不顺手」
→ React 在生态(可抄)· 效率(快一个量级)· 质量(AI 补测+易 mock)· 灵活(组件级插件)四条上,都比 Angular 更适合 AI 来写。
